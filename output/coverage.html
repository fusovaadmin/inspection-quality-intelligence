1 · Coverage — what is the plan assigned to find?

A control plan lists the characteristics somebody thought to write down. The floor produces whatever it produces. The gap between those two sets is invisible unless something computes it, because a failure mode nobody is assigned to detect generates no alert, no chart, and no absence anyone notices.

2 · Condition — can the station still see what it was assigned to see?

A robot does a home-position check before it trusts its own coordinates. An inspection cell should do the same, for the same reason: everything downstream is worthless if the instrument has quietly moved. So before it judges any production part, the station measures a known reference coupon (CAL-COUPON-001) and inspects its own fixture. Because the answer is known in advance, this is not a proxy for the station's condition — bias and repeatability are measured directly.

Four steps, each go / no-go, in this order:
  1. Imaging — brightness and sharpness on the coupon, and the grade of a reference 2D DataMatrix. Barcode grade is the best single summary of imaging health: it degrades with light, focus, contrast and optics all at once, on a published scale.
  2. Measurement — measure a feature of known length. The gap from truth is bias; the spread over repeated reads is repeatability.
  3. Tooling — the station inspects the cell's own fixture: locator wear, clamp position. A vision system is perfectly capable of looking at the tooling that holds the part.
  4. Production — only now does it judge real units against the control plan.

Which step fails decides which inspections you lose, and they point opposite ways. A failed imaging step costs the visual checks and spares the measurement — finding an edge survives poor contrast. A failed measurement or tooling step costs the dimensional work and spares the visual checks — the part stops landing in the same place, and that error is added straight into a size reading, but the feature is still in the field of view. Neither shows up in yield or capability, because in both cases nothing is failing. The station has stopped being able to do part of its job.

3 · Operating point — what does being wrong cost here?

There are only two ways an inspection can be wrong, and they cost different amounts.
  • It rejects a good part. You scrap or rework something that was fine. That gets more expensive the further down the line you are, because more work has gone into the part.
  • It passes a bad part. The defect moves on. That costs whatever it takes to find and fix it wherever it does get caught — the next station, final test, or the customer.

So every station faces one question: how many good parts is it worth wrongly rejecting in order to stop one bad part getting through? That number is the last column in both tables below. A big number means set the station to catch everything, even at the price of scrapping good parts. A number near 1 means being trigger-happy costs about as much as letting things through, so it has to be tuned carefully both ways.

Costs are in relative value units — a part at the first station is worth 1. No dollar figures appear anywhere, because that would imply a costing study nobody has done.

The last station on the line has to be nearly as strict as the first oneinsight · DIM-OOS
Every station faces one question: how many good parts is it worth wrongly rejecting in order to stop one bad part getting through? The obvious answer is that it depends how far down the line you are, because a part near the end has more work built into it and scrapping it hurts more. That turns out to be only half right. What actually decides it is who catches the defect NEXT if this station misses it. On LINE-A, checking Dimensional out of spec (DIM-OOS): if S1 misses it, S2 catches it straight away — so S1 can afford to wrongly reject about 4.7 good parts to stop one bad one getting through. If S2 misses it, S3 catches it: about 3.8. But if S3 misses it, nothing does until FINAL-TEST, which is expensive — so S3 goes back UP to about 4.5, even though it is handling the most valuable parts on the line. Being last is not what matters — being the last one who can see it is. The half that does hold is that wrongly rejecting a good part gets steadily more expensive the further down the line you go: that was true in all 81 of 81 assumption combinations tested. The tidier version of the rule held in only 6 of 81.

4 · Which conclusions survived being stress-tested

Every cost and acceptance figure on this page is an assumption, not a measurement. So no conclusion is reported from one set of numbers. Each claim is re-tested against every combination in a range of plausible assumptions, and what is reported is how often it held — including when it did not.

Claim in plain termsHeld inVerdict
Scrapping a good part gets more expensive the further down the line you are 81 / 81 HOLDS
The further down the line, the less aggressive a station should be 6 / 81 DOES NOT HOLD
A failed imaging self-test costs the visual checks and spares the measurement 81 / 81 HOLDS
A failed measurement or tooling self-test costs the size checks and spares the visual ones 81 / 81 HOLDS

The second row is the interesting one, and it is the reason this section exists. The intuitive rule is that a station near the end of the line should be less trigger-happy, because the parts it is scrapping are worth more. Half of that is right — scrapping a good part really does get more expensive every step down the line, in every single combination tested. But the other half does not survive: what actually decides how aggressive a station should be is who catches the defect next if this one misses it. A station sitting last, right before an expensive final test, has to be nearly as strict as the first station on the line. A test in tests/test_coverage.py asserts this claim fails, so quietly tuning the assumptions until the tidy story holds turns the suite red instead of going unnoticed.

The last two rows exclude combinations where the limit was set so loose that nothing was lost at all — 0 and 0 respectively. Those are vacuous, not counterexamples, and counting them as failures would understate a claim that is actually holding.

5 · What this does not claim

Reads inspection results and cell process measures. Reports a condition against an acceptance level and a coverage gap against a control plan. Makes no statement about when any component will stop working, and handles no image data.

  • No image data and no vision model. This reads inspection results and cell process measures — illumination, exposure, focus score, fixture repeatability. Scalars, not pixels.
  • No failure prediction. It reports a condition against an acceptance level. Saying when a lamp will stop working is a prognostics claim and nothing here supports one — there is no failure history and no model fitted to failures. A test asserts that no finding contains forecast language.
  • The cost and acceptance figures are assumptions, not measurements. They are marked PLACEHOLDER in config with the study that would earn them named alongside. That is why the sweep exists.
  • The data is synthetic and generated in this repository with the signals injected on purpose, so the checks have something real to catch and the tests can assert on known numbers.
