Events on a different day
A work order was closed two days early — the line kept running. ERP shows no open work order for LINE-C on 2026-04-27, 2026-04-28, yet 1,080 units were inspected there. Caught by the range join: an event outside every [sched_start, sched_end] window keeps its row with a NULL work order instead of silently disappearing.
MES kept booking shifts to that same closed work order. 18 shift records name a work order ERP shows already closed on those dates. Neither system can see this on its own — it only exists in the join.
An MES logger outage hid 172 events. 3 shifts (S6, shift B) have no MES record at all, though the stations logged production the whole time. Driven from the MES side, this outage is structurally invisible — a shift that was never written cannot appear in a result set. The join has to be driven from what was actually produced.
QMS and the stations disagree. 15 NCRs reference serials that were never inspected, and 10 more carry a defect category that contradicts the code the station recorded. Found by canonicalizing two serial formats (SN-S3-00-0142 ↔ s3-00-0142) and mapping the human taxonomy onto the machine one.

The expensive assumption: production day ≠ calendar day

MES records production against a production day, not a calendar day. Shift C runs 22:00 → 06:00, so everything it makes belongs to the day it started — an event stamped 02:00 on the 10th was made on the production day of the 9th. Joining MES to the floor on CAST(ts AS DATE) mis-assigns 24,017 events — 24.92% of the dataset. That is not a crash. It is a dashboard that is quietly wrong for a quarter of every night, and nobody files a bug against it.
